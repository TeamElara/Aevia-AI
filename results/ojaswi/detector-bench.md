# Detector latency

Rules only (classifier off), warm, single thread. Apple M3, darwin arm64, Node v26.8.1. Generated by `npm run bench` in `packages/detectors`.

| Input | Runs | p50 ms | p95 ms | max ms |
| --- | --- | --- | --- | --- |
| Benign corpus (110 prompts) | 2200 | 0.14 | 0.25 | 0.43 |
| Attacks and PII (8) | 400 | 0.15 | 0.29 | 0.50 |
| Dev set prompts (20) | 1000 | 0.14 | 0.22 | 0.34 |
| 1,000-char document | 200 | 0.78 | 0.86 | 1.01 |
| 5,000-char document | 100 | 3.52 | 3.78 | 3.98 |
| 20,000-char document | 30 | 13.9 | 15.0 | 16.3 |
| 100,000-char document (limit) | 10 | 54.7 | 61.0 | 61.0 |

Per message: the gateway scans each message, the joined user turns and the response, so a chat turn is a few of these calls. The DeBERTa classifier adds about 10 ms (fp32) or 6 ms (int8) per 1,500-char window when enabled (Alwaz's spike). Dev prompts only; held-out and robustness files are not used.
