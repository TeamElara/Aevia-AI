## Findings (issue drafts)

No source was changed (Part A rule: no decision-code changes before the final demo). Each finding below has a one-line fix for the team to approve.

### Issue 1 (critical): `STRUCT` in `src/injection.ts:84` is cubic on newline runs and freezes the gateway

- **Pattern:** `^\s*(?:#{2,}|\[)?\s*(?:system|assistant|developer)\s*[:\]]` with the `m` flag. `\s` also matches newlines, so from every line start the two `\s*` around the optional group rescan the rest of a newline run.
- **Measured:**

  | Newlines | Time |
  | --- | --- |
  | 1,000 | 0.3 s |
  | 2,000 | 2.4 s |
  | 4,000 | 18.8 s |

  Time grows about 8× per doubling (cubic). 50,000 newlines would run for hours.
- **Impact:** `detectInjection` runs synchronously inside `detectAll`, so it blocks the Node event loop. The scanner's 5 s `Promise.race` timeout cannot pre-empt synchronous code. One prompt of a few KB of blank lines, well under `MAX_SCAN_CHARS`, freezes the gateway for every user.
- **Fix:** use `[ \t]*` instead of `\s*` in the line-start alternative (`^[ \t]*(?:#{2,}|\[)?[ \t]*(?:system|assistant|developer)[ \t]*[:\]]`). With the `m` flag every line still gets its own `^`, so real role tags match the same; only newline-crossing is removed. Add a regression test (4,000 newlines under 50 ms).

### Issue 2 (medium): markdown link/image regexes in `src/links.ts:29-30` are quadratic

- **Pattern:** `\(\s*<?([^)\s>]+)` has no upper bound, so on `![a](` repeated, every candidate rescans to the end of the text.
- **Measured:** 2.5 s at 50 KB.
- **Impact:** `findLinks` runs on model responses (`sanitiseLinks`), so it needs a model that echoes a long crafted string.
- **Fix:** bound the URL part, e.g. `([^)\s>]{1,2048})`, and the same in the image pattern.

### Issue 3 (low): `normalise` and `decodeBlocks` take 60–75 ms on some 50 KB inputs

Just over the 50 ms bar; linear, not a blow-up. Optional: skip `decodeBlocks` candidates longer than 16 KB.
