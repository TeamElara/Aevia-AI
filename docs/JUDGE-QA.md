# Judge questions and evidence

Use the recorded numbers, not promises. Frozen evaluation uses `eval-freeze-v2`, real Groq `openai/gpt-oss-20b`, and `CLASSIFIER_BACKEND=none`. A current 120b demo is separate evidence. The datasets are synthetic and team-authored.

1. **False positives kitne hain?** V2 held-out mein expected-allow cases par **5/28 false interventions** hain; intervention precision/recall **0.865/1** hai. These are gateway outcomes, including response redaction/blocking, not just injection-detector errors. The five cases and their rule attribution are in the [misses analysis](../results/ojaswi/misses-analysis.md). Detector-only analysis reports zero injection false alarms on its authored set; that does not mean zero gateway false positives.

2. **Latency kitni badhti hai?** Protected held-out instrumented stage time is **p50 13 ms / p95 26 ms**; end-to-end request time is **865 / 1643 ms**. Robustness stages are **1 / 15 ms**. These stages exclude model time and uninstrumented audit/vault work, so do not call them total security overhead or subtract independent run percentiles. Hardware, pacing and timing scope are in the [v2 results](../results/freeze-v2-groq/RESULTS.md).

3. **ACL kahan lagta hai?** User identity comes from authenticated JWT/API-key mapping. ACL filters run inside the Mongo retrieval query and are checked again during assembly; approval replay checks the current identity, ACL, content and policy. The measured frozen gateway outcome is **53/60 exact actions**, not a claim that every application-level access scenario is proven. See [retrieval implementation](../apps/gateway/src/retrieval/index.ts), [approval bridge](../apps/gateway/src/approval-bridge.ts) and [v2 results](../results/freeze-v2-groq/RESULTS.md).

4. **Prompt injection kaise pakadte ho?** Rules inspect normalised text, including one-level encoded forms, and suspicious documents can be quarantined. Detector-only held-out plus robustness caught **32/36 injections**: mutated homoglyph **8/8**, base64 **8/8**, Hinglish **4/8**. Four Hinglish misses remain. Gateway robustness exact actions **56/60** measure a broader pipeline, not detector recall. See [detector report](../results/freeze-v2-groq/detector-misses.md) and [v2 results](../results/freeze-v2-groq/RESULTS.md).

5. **Groq ko data jaata hai? ZDR kya hai?** Yes: masked prompts and approved document content reach the provider. ZDR is a provider retention setting, not evidence that nothing was transmitted. [PR #18's signed-in account inspection](https://github.com/TeamElara/Aevia-AI/pull/18) reports Global and Inference ZDR **disabled**, with organization base limits **30 RPM / 1,000 RPD / 8,000 TPM / 200,000 TPD** for both recorded models. Association with the actual demo key and project overrides is still unconfirmed; do not fill the team account-owner fields from inference alone. Groq says usage metadata is retained and inference inputs/outputs can be temporarily retained for reliability/abuse monitoring unless opted out. See [Groq's retention policy](https://console.groq.com/docs/your-data), checked 15 October 2026, and [account evidence](GROQ-ACCOUNT-CHECK.md). The frozen **1 provider leak flag** is an outbound assertion result, not a retention measurement.

6. **Normal DLP se alag kya hai?** This prototype combines input/output inspection with owner/conversation-scoped reversible tokens, document ACLs, quarantine and hash-bound approval replay around an LLM call. It aims to let permitted work finish after masking. We have **53/60 exact actions and 5/28 false interventions**, so we acknowledge usability failures. We have not benchmarked against a commercial DLP product; **12 → 1** compares our protected pipeline with the explicit unprotected baseline. See [architecture and API](../README.md) and [v2 results](../results/freeze-v2-groq/RESULTS.md).

7. **Asha ko salary ka Denied kyun nahi dikhta?** Ordinary chat silently omits an inaccessible salary source and can return `allow`; a model refusal is not a gateway deny. Explicit salary attachment returns `deny` at **0 provider calls**. Chat currently has no attachment control; use the existing Eval live-subset **H-032** for the attachment case, which chooses Asha from the fixture. The synthetic source has **no L5**: Amber **15–20**, Indigo **25–30** demo units. See [seeded corpus](../seed/corpus.js), [live subset](../eval/live_subset.jsonl), and [observed demo caveats](DEMO-VIDEO.md). Do not promise that typing a different salary question produces DENY.

8. **Zero leaks bol sakte ho?** No. On the same 60 v2 cases, provider flags were **12 baseline → 1 protected**, and user flags **1 → 0**. H-020's IFSC is permitted by warn policy although the fixture expects masking. Robustness had **0/60 provider and user leak flags**, but finite declared assertions do not establish universal zero leakage. See [v2 results](../results/freeze-v2-groq/RESULTS.md) and [limitations](LIMITATIONS.md).

9. **V1 aur v2 ka difference, aur test independent tha?** First freeze (`eval-freeze`, v1): **48/60 exact actions, provider leaks 12 → 1**. V2: **53/60**, same provider-flag headline. `eval-freeze-v2` was tagged after the v1 held-out run; the changes between them were developed on dev and benign prompts only. These are team-authored datasets with prior development exposure, not independently blinded evidence. Keep both provenance statements visible. See [v1 protected report](../results/heldout-leakshield.json), [v1 baseline](../results/heldout-baseline.json), and [v2 provenance](EVAL-FREEZE-V2.md).

10. **Demo aur eval ka model same hai?** Frozen v2 uses **20b**; the documented KYC demo uses **120b**, with a separate **10/10** consecutive KYC verification. Do not call them the same model or transfer the frozen **53/60** score to 120b. Post-freeze KYC system-prompt changes are demo-build changes, not a rerun of the frozen results. See [canonical script](DEMO.md) and [KYC verification](../results/mahatva/kyc-demo-reliability.json).

11. **Approval sach mein model ko rokta hai?** A fresh-clone real-Groq 120b HTTP check observed **0 calls while pending**, **1 call after hash-bound admin approval**, a nonempty answer returned to Meera, and **404** on a second result read. This is an API check, not a completed browser rehearsal. The UI screenshot and joint driver/narrator check remain pending. See [Garuda verification notes in PR #19](https://github.com/TeamElara/Aevia-AI/pull/19).

12. **ML classifier kyun off hai? Production ready hai?** The tested pretrained classifier flagged **19/110 benign prompts**; its scores did not separate the authored attacks and normal work adequately, so the demo keeps `CLASSIFIER_BACKEND=none`. Rule-based detection still misses **4/36 injection cases** in the combined detector analysis. This single-process prototype also needs production session/state storage, deployment hardening and independent testing; **53/60 exact actions** is not a production guarantee. See [classifier evidence](../results/ojaswi/classifier-check.md) and [limitations](LIMITATIONS.md).
