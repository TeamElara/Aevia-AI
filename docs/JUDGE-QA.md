# Judge questions and evidence

These answers use synthetic, team-authored evidence. Frozen v2 uses `eval-freeze-v2`, Groq `openai/gpt-oss-20b` and `CLASSIFIER_BACKEND=none`. The current 120b demo and machine checks are separate; do not transfer frozen scores to another build or model.

1. **False positive kitne hain?** V2 held-out has **5/28 false interventions on expected-allow cases**, with intervention precision/recall **0.865/1**. These are gateway outcomes, including response redaction/blocking; zero observed detector-only injection false alarms does not mean zero gateway false positives. See [v2 results](../results/freeze-v2-groq/RESULTS.md) and [five-case attribution](../results/ojaswi/misses-analysis.md).

2. **Latency kitni badhti hai?** Protected held-out instrumented stages: **p50 13 ms / p95 26 ms**; end-to-end request time: **865 / 1643 ms**. Robustness stages: **1 / 15 ms**. Stage timing excludes model time and uninstrumented audit/vault work, so it is not total security overhead. Do not subtract percentiles from separate runs. See [timing scope and hardware](../results/freeze-v2-groq/RESULTS.md).

3. **ACL kahan lagta hai?** JWT/API-key identity determines access. ACL filtering runs inside the Mongo retrieval query, with another check at assembly; approval replay rechecks current access/content/policy. Explicit unauthorised salary attachment is denied at **0 provider calls**. The aggregate **53/60 exact actions** is not a proof of all access scenarios. See [retrieval](../apps/gateway/src/retrieval/index.js), [approval bridge](../apps/gateway/src/approval-bridge.ts) and [recorded demo evidence](DEMO-VIDEO.md).

4. **Injection kaise pakadte ho?** Normalisation and rules inspect intent, targets and structure, including **one-level** encoded forms. Suspicious sources can be quarantined before the provider call. Combined detector analysis caught **32/36 injections**; homoglyph and base64 mutations were **8/8** each. Gateway robustness **56/60 exact actions** measures the whole pipeline, not detector recall. See [detector evidence](../results/freeze-v2-groq/detector-misses.md) and [v2 results](../results/freeze-v2-groq/RESULTS.md).

5. **Kya data Groq tak jaata hai?** Yes: masked prompts and approved content reach Groq. In the signed-in Personal organization we checked, inference **ZDR is disabled**, so we do not claim zero retention. Recorded organization base limits for both models are **30 RPM / 1,000 RPD / 8,000 TPM / 200,000 TPD**. Demo-key association/project overrides were not independently established. Groq retains usage metadata and permits temporary input/output retention for reliability/abuse monitoring. See the [judge wording and scope](GROQ-ACCOUNT-CHECK.md), [authenticated metadata](../results/mahatva/groq-account-console.json) and [provider policy](https://console.groq.com/docs/your-data), checked 15 October 2026.

6. **Normal DLP se alag kya hai?** The prototype combines inspection with conversation/owner-scoped reversible tokens, document ACLs, quarantine and approval replay around LLM calls. It aims to complete permitted work after masking. V2 recorded **53/60 exact actions**, **5/28 false interventions** and **12 → 1 provider-leak flags** against its explicit unprotected baseline. No commercial DLP comparison was run. See [pipeline](../apps/gateway/src/pipeline.ts) and [measured results](../results/freeze-v2-groq/RESULTS.md).

7. **Hinglish misses kitne hain?** Detector-only mutated Hinglish attacks: **4/8 caught, 4 missed**, cases R-032/R-033/R-034/R-037. Overall injection detection was **32/36**, and detector mutation retention **20/24**. Gateway robustness **56/60** includes ACL/output interventions and is a separate metric. These vocabulary gaps remain; no frozen rules were retuned after viewing results. See [detector report](../results/freeze-v2-groq/detector-misses.md) and [misses analysis](../results/ojaswi/misses-analysis.md).

8. **Asha ko salary pe Denied kab aata hai?** With an explicit salary-document attachment: `deny`, **0 calls**. Ordinary Chat can silently omit the inaccessible source and return `allow`; a model refusal is not gateway DENY. Chat has no attach control. In the console use **Eval → Run live subset**, whose **H-032** fixture selects Asha and carries the attachment. There is no L5 band: Amber **15–20**, Indigo **25–30** demo units. See [canonical script](DEMO.md), [fixture](../eval/live_subset.jsonl) and [seed source](../seed/corpus.js).

9. **Fingerprints paraphrase pakadte hain kya?** Not reliably. The current HMAC fingerprints use **8-word shingles**, requiring **2 distinct matching shingles** by default. They detect sufficiently overlapping copying after normalisation, not semantic equivalence. Reworded disclosure can evade that check; **0/60 robustness provider flags** are finite fixture assertions, not a paraphrase-safety guarantee. See [fingerprint implementation](../apps/gateway/src/retrieval/fingerprints.js), [limitations](LIMITATIONS.md) and [v2 results](../results/freeze-v2-groq/RESULTS.md).

10. **Ollama pe switch kaise hota hai?** Pull/configure the local model first. Stop the gateway, set private `.env` `LLM_PROVIDER=ollama`, restart with `npm start`, then start a new chat. Switching back uses `groq` and another restart. The prepared Windows laptop measured **2.952 s** Groq→Ollama to its first answer, including restart, excluding manual editing; this is one observed switch, not an outage guarantee. Keep the approval scene on Groq: authorised local Garuda does not need external-provider approval. See [startup and switch instructions](DEMO-LAPTOP.md) and [machine evidence](../results/mahatva/demo-laptop-readiness.json).

11. **Eval kaise freeze kiya?** V1 (`eval-freeze`): **48/60 exact actions, provider leaks 12 → 1**. V2 (`eval-freeze-v2`, `05d1afc`, 15 October 17:02:11 IST): **53/60**, robustness **56/60**, same provider-flag headline. V2 was tagged after the v1 held-out run; intervening changes were developed on dev and benign prompts only. Reports retain frozen commit, dataset hashes, expectations and attachment-contract provenance. These are team-authored sets with prior exposure, not a new independently blinded test. See [freeze record](EVAL-FREEZE-V2.md), [v1 protected](../results/heldout-leakshield.json), [v1 baseline](../results/heldout-baseline.json) and [v2 report](../results/freeze-v2-groq/RESULTS.md).

12. **Production me deploy kaise hoga?** The supplied Compose setup is a local starting point: gateway **8080** and Mongo **27017** bind to loopback, and the console has its separate build. This is a **single-process** prototype; restart loses pending in-memory state. Production needs real identity with demo auth disabled, managed secrets, private database access, a TLS entry point, shared secure conversation/approval state, retention operations and load/security testing. Those are required future deployment work, not completed features. **53/60** frozen actions is not production certification. See [deployment starting point](../docker-compose.yml), [README](../README.md) and [limitations](LIMITATIONS.md).


## Detection evidence supplement — Ojaswi

Integrated from Ojaswi's `ojaswi/judge-qa-detection` contribution (`f5bd9ae`), with the original author retained in Git. This supplements the same canonical Q&A page; it does not create a competing script or change frozen measurements.

**How the rules work.** Normalisation includes NFKC, zero-width removal, homoglyph folding and one-level encoded views with offsets mapped back to the original text. Aadhaar/card candidates receive checksum validation; injection rules combine intent and target with contextual damping. Injection scores at least **0.85** block; **0.60–0.85** warn under the frozen policy. The classifier stays off after **19/110** benign flags. Sources: [detectors](../packages/detectors/src/index.ts), [policy](../apps/gateway/policy.yaml), [classifier evidence](../results/ojaswi/classifier-check.md).

**Post-freeze red-team check.** Ojaswi ran **50 new synthetic attacks** through the full gateway with a **simulated loopback provider**: **32 stopped before the provider, 1 warned only, 17 bypassed, 0 errors**. Bypasses were **7/10 Hinglish, 3/8 Devanagari, 4/8 roleplay and 3/6 split-line** cases. The report's family rows show 6/6 zero-width cases plus six single-case encodings stopped: **12/12 encoding cases**, rather than the draft Q&A's 11. A bypass means the request passed gateway controls in this run; it does not demonstrate real-model exfiltration. This is separate from the frozen 20b provider runs and does not alter their 12 → 1 headline. [Pinned red-team report](https://github.com/TeamElara/Aevia-AI/blob/d7416b5ca3a3513a290ba2a814b56a9810484a2c/results/ojaswi/redteam.md).

**Latency and ReDoS are different measurements.** On mixed realistic inputs, detector-only `detectAll` p50/p95 was **1.02/1.18 ms at 1 KB**, **12.1/12.7 ms at 10 KB**, and **43.7/47.6 ms at 50 KB**, on Apple M3 / Node 26.8.1. That is not a worst-case bound or the frozen gateway overhead. The adversarial audit covered **111 regexes × 51 inputs of 50,000 characters**, finding a structural-injection pattern exceeding the **15-second worker cutoff**, and two markdown patterns around **2.5 seconds**. Synchronous scanning can stall the gateway event loop; the ordinary scanner timeout cannot preempt a running regex. [Pinned benchmark](https://github.com/TeamElara/Aevia-AI/blob/3e8fb05717333b0b211f983182ef1fca57153e61/results/ojaswi/bench.md) · [Pinned audit](https://github.com/TeamElara/Aevia-AI/blob/b52ed3b75ba06c0b54ef9a54434eef7b03af92e8/results/ojaswi/redos-audit.md).

**Hotfix status at this Q&A update:** Ojaswi has prepared `ojaswi/redos-hotfix` (`0aca008`) with structural whitespace/link-rescanning changes and performance regressions. It is **not yet merged**, so do not say the deployed gateway is fixed. The reviewed post-freeze hotfix and Mahatva's rerun must be recorded separately from `eval-freeze-v2`; that tag and its reports remain unchanged. The broader audit also reports slow normalisation/decoding cases, so fixing the two known patterns is not proof that every 50 KB input completes within 50 ms. [Prepared hotfix](https://github.com/TeamElara/Aevia-AI/commit/0aca0083ec43d966d4f2a966cbe36462cdacea0f).

**IFSC/v3 boundary.** H-020 remains the **1** provider flag under frozen `ifsc: warn`. Detection proposes masking in v3; applying it belongs to the policy owner after the demo, followed by a new freeze and evaluation. It has not closed the historical leak retroactively. Future Hinglish/roleplay and answer-side false-positive work must use new dev cases and a blind held-out set withheld from Detection, not retuning against disclosed cases. [Proposed IFSC decision](https://github.com/TeamElara/Aevia-AI/blob/f025f90da6fe728a7bcbc2b935548d4d1b8fedb5/docs/decisions/IFSC-POLICY.md).
